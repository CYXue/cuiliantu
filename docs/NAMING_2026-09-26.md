## 一、结论先行

**推荐命名：`图淬` / `TuCui`**

- 中文产品名：**图淬**（tú cuì）
- 英文 / 代码标识：**TuCui**（小写 `tucui`，Cargo lib 名 `tucui_lib`）
- 结构：领域字「图」+ 意象字「淬」，与既有品牌 `屏迹 / PingJi`（领域字 + 意象字 + 拼音即英文名）完全同构
- 语义：淬火＝金属加热后急速冷却而变硬变强 → 图片经淬炼，体积更小、更"硬核"可用；同时暗合本项目的核心动作（压到目标大小、按证件照尺寸裁切、转格式＝把图"炼"到合规）
- 查重：公开网页检索无同名软件 / 应用 / 仓库品牌；`tucui.app` `tucui.dev` `tucui.com` 均无解析（可注册）；npm `tucui` 未被占用

## 六、落地风险与注意事项（改名时必须处理）

1. **localStorage 数据迁移（最易踩）**：`image-crunch-templates.v1` 存着用户的自定义参数模板。直接改 key = 用户模板"蒸发"。两种处置：
   - 简单：接受一次性重置，在 Release Notes 写明；
   - 稳妥：读取时做一次 key 兜底——新 key 不存在则读旧 key，写入新 key 后删除旧 key（约 10 行代码，一次性迁移逻辑）。
2. **主题/语言偏好重置**：`image-crunch-theme` / `image-crunch-lang` 同理，影响小（用户重选一次即可），建议同样加兜底读取。
3. **更新检查**：`GITHUB_REPO` 未改 → 更新检查永远查上游仓库（会拿到别人的 release）。改名与建仓必须同批完成，否则发布前功能实际不可用。
4. **Cargo.lock**：改 `Cargo.toml` 的 `name` 后必须跑一次 `cargo check`（自动更新 lock 中的包名），不要手改 lock。
5. **临时目录模板**：`image-crunch-*` 改 `tucui-*`，旧临时目录不会被清理（残留于系统 temp），可接受。
6. **目录重命名**：`image-crunch/` → `tucui/` 属于独立动作（牵动 CI 路径、文档、worktree），建议单独一个 PR，不与代码改名混在一起。
7. **窗口标题中文化**：Tauri 的 `title` 是静态配置。若要中文界面显示「图淬」、英文界面显示「TuCui」，需在前端 `onMount` 按当前语言 `setTitle()`（`@tauri-apps/api/window`），属可选增强，不在本次改名范围。
